CENSUS AI — BACKEND API CONTRACT
================================

IMPORTANT:
The backend is maintained by another teammate.

The frontend must NOT modify the backend.

Backend server:
http://localhost:4000

The backend is a FastAPI application.

CURRENT ENDPOINTS
=================

1. GET /api/reports

Full URL:

http://localhost:4000/api/reports

Returns an array of reports.

Reports are sorted by priority_score descending by the backend.

Example response:

[
  {
    "id": "b02e17ac-9dd8-4a38-ba26-3dc0bfe8e9cf",
    "category": "pothole",
    "priority": "High",
    "priority_score": 70,
    "status": "reported",
    "photo_url": "http://localhost:4000/uploads/seed1.jpg",
    "location": "MG Road near bus stop",
    "description": "Large pothole causing traffic",
    "created_at": "2026-09-20T18:15:19Z",
    "updated_at": "2026-09-20T18:15:19Z"
  }
]


2. GET /api/reports/{id}

Example:

GET http://localhost:4000/api/reports/b02e17ac-9dd8-4a38-ba26-3dc0bfe8e9cf

IMPORTANT:
IDs are UUIDs generated by the backend.

Do NOT assume IDs such as:
demo-rep-001
demo-rep-002

exist in the real backend.

Use an actual ID returned by GET /api/reports.


3. POST /api/reports

Full URL:

http://localhost:4000/api/reports

Request type:

multipart/form-data

Required field:

photo

Required field:

location

Optional field:

description

Example:

photo = uploaded image file
location = "MG Road near bus stop"
description = "Large pothole causing traffic"

The backend processes the uploaded image using Gemini vision classification.

It then calculates category and priority.

The response contains the complete report object.

CURRENT FRONTEND ENVIRONMENT
============================

VITE_API_BASE_URL=http://localhost:4000

VITE_USE_MOCK_DATA=true/false

When:

VITE_USE_MOCK_DATA=false

the dashboard MUST use the live backend.

When:

VITE_USE_MOCK_DATA=true

the dashboard may use local demo/mock data.


IMPORTANT FRONTEND RULES
========================

DO NOT:

- modify main.py
- modify backend routes
- modify backend schema
- create competing backend routes
- assume backend endpoints that don't exist
- silently replace failed live API requests with mock data
- rename backend fields

The frontend must adapt to the existing backend.


LIVE FEATURES
=============

The following should use the actual backend:

Dashboard:
GET /api/reports

Complaint details:
GET /api/reports/{id}

File Complaint:
POST /api/reports


FRONTEND-ONLY / DEMO FEATURES
=============================

The current backend does NOT provide:

- geographic coordinates
- heatmap API
- announcements API
- services API
- feedback API
- authentication
- citizen-specific complaint ownership
- average resolution time
- notification API
- emergency API

Therefore these features may exist visually in the frontend,
but must use clearly separated demo/mock data.

Do NOT pretend these are live backend features.


ANALYTICS
=========

Analytics may be calculated from the latest:

GET /api/reports

For example:

- total complaints
- high priority count
- medium priority count
- low priority count
- category distribution

Do NOT create a fake analytics backend endpoint.


HEATMAP
=======

The current backend does not provide latitude/longitude.

Therefore the heatmap is DEMO DATA only.

Clearly label it:

Demo Data

Do not imply that it represents real geographic complaint data.


AVERAGE RESOLUTION TIME
=======================

The current backend does not provide enough data to calculate
actual resolution duration.

Therefore:

"Average Resolution Time"

must be treated as demo data until the backend is expanded.

Do not create a fake endpoint.
